# Phase 3 Glossary

[[Phase 3 - Start Here|Home]] · [[Phase 1 Glossary]] · [[Phase 2 Glossary]]

Simple meanings for the words used in Phase 3. Each one links to the note that explains it.

## A to C

- **ACID:** the four promises of a transaction. [[52 Transactions and ACID#ACID|More]]
- **Adapter:** makes an incompatible interface fit. [[43 Design Patterns#Adapter|More]]
- **Anti-pattern:** a common "solution" that causes trouble. [[43 Design Patterns#Anti-Patterns|More]]
- **Artifact:** the built package a pipeline produces. [[49 Continuous Integration and Delivery#Build Once, Deploy Everywhere|More]]
- **Assembly:** a readable form of CPU instructions. [[35 Computer Organization and Architecture#From Your Code to Machine Code|More]]
- **Async:** one thread that switches tasks whenever one has to wait. [[37 Concurrency and Parallelism#Async and Event Loops|More]]
- **Attack surface:** every place an attacker could get in. [[45 Security Fundamentals#Reduce the Attack Surface|More]]
- **B-tree:** the short, wide tree behind most database indexes. [[51 Indexing#Inside an Index - The B-tree|More]]
- **Branch prediction:** the CPU guessing which way an `if` will go. [[35 Computer Organization and Architecture#Branch Prediction|More]]
- **Buffer overflow:** writing past the end of a memory block. [[38 Memory Management#Buffer Overflow|More]]
- **Cache line:** the block of memory that a CPU loads at once. [[35 Computer Organization and Architecture#Locality|More]]
- **cgroups:** a kernel feature that limits what a process can use. [[48 Docker#What Is a Container?|More]]
- **Characterization test:** a test that records what old code does today. [[41 Refactoring#Characterization Tests|More]]
- **CI and CD:** automatically testing and shipping every change. [[49 Continuous Integration and Delivery#The Three Terms|More]]
- **CIA triad:** confidentiality, integrity and availability. [[45 Security Fundamentals#What Are We Protecting?|More]]
- **Code smell:** a sign that code may have a design problem. [[41 Refactoring#Code Smells|More]]
- **Commit:** making a transaction's changes permanent. [[52 Transactions and ACID#Commit and Rollback|More]]
- **Composite index:** an index on several columns. [[51 Indexing#Composite Indexes and Column Order|More]]
- **Compose:** a tool that runs several containers together. [[48 Docker#Docker Compose|More]]
- **Concurrency:** dealing with many tasks at once. [[37 Concurrency and Parallelism#The Big Idea|More]]
- **Container:** a process with walls around it. [[48 Docker#What Is a Container?|More]]
- **Context switch:** changing which thread is on the CPU. [[36 Operating Systems#Context Switches|More]]
- **Contract test:** checks the agreement between two services. [[47 Integration Testing#Contract Testing|More]]
- **Covering index:** an index holding everything a query needs. [[51 Indexing#Covering Indexes|More]]
- **Critical section:** code that touches shared data. [[37 Concurrency and Parallelism#Race Conditions|More]]
- **Cursor pagination:** "give me the rows after this one". [[44 API Design#Pagination|More]]

## D to H

- **Dangling pointer:** a pointer to memory that was freed. [[38 Memory Management#Dangling Pointer|More]]
- **Deadlock:** threads waiting for each other forever. [[37 Concurrency and Parallelism#Deadlocks|More]]
- **Decorator:** wraps something to add behaviour. [[43 Design Patterns#Decorator|More]]
- **Defense in depth:** many layers of protection. [[45 Security Fundamentals#Defense in Depth|More]]
- **Dependency injection:** passing in what a class needs. [[43 Design Patterns#Dependency Injection|More]]
- **Design pattern:** a proven shape for a common problem. [[43 Design Patterns#The Big Idea|More]]
- **Dockerfile:** the recipe for an image. [[48 Docker#Writing a Dockerfile|More]]
- **DORA metrics:** four numbers that measure delivery. [[39 Software Development Lifecycle#Measuring Delivery - DORA|More]]
- **Event loop:** runs one ready task at a time. [[37 Concurrency and Parallelism#Async and Event Loops|More]]
- **Exit code:** a number saying how a process ended. [[36 Operating Systems#Creating Processes|More]]
- **Expand and contract:** changing a schema in safe stages. [[50 Database Design#Expand and Contract|More]]
- **Facade:** a simple front for a complicated system. [[43 Design Patterns#Facade|More]]
- **Factory:** a place that decides which object to create. [[43 Design Patterns#Factory|More]]
- **Feature flag:** a switch that turns a feature on or off. [[49 Continuous Integration and Delivery#Feature Flags|More]]
- **Fetch, decode, execute:** the CPU's endless loop. [[35 Computer Organization and Architecture#How the CPU Runs Code|More]]
- **Fixture:** prepares what a test needs. [[47 Integration Testing#What an Integration Test Looks Like|More]]
- **Flaky test:** a test that passes or fails at random. [[47 Integration Testing#Flaky Tests|More]]
- **Floating point:** how computers store decimals, approximately. [[35 Computer Organization and Architecture#Decimal Numbers - Floating Point|More]]
- **Garbage collector:** frees memory that can't be reached. [[38 Memory Management#Garbage Collection|More]]
- **GIL:** the Python lock that allows one thread at a time to run Python code. [[37 Concurrency and Parallelism#Threads in Python|More]]
- **Heap (memory):** where long-lived data goes. [[38 Memory Management#Stack and Heap|More]]

## I to O

- **Idempotency key:** lets a server recognise a retried request. [[44 API Design#Idempotency - Safe Retries|More]]
- **IDOR:** reaching other people's data by changing an ID. [[46 OWASP Top 10#A01 Broken Access Control|More]]
- **Image:** a frozen package of an app. [[48 Docker#The Three Key Words|More]]
- **Instruction set:** the commands that a CPU understands. [[35 Computer Organization and Architecture#From Your Code to Machine Code|More]]
- **Integer overflow:** a number passing its limit and wrapping around. [[35 Computer Organization and Architecture#Integer Overflow|More]]
- **Integration test:** checks that parts work together. [[47 Integration Testing#The Big Idea|More]]
- **Isolation level:** how much transactions can see of each other. [[52 Transactions and ACID#Isolation Levels|More]]
- **Kernel:** the core of the operating system. [[36 Operating Systems#Kernel and User Space|More]]
- **Layer (Docker):** one cached step of an image. [[48 Docker#Layers and Caching|More]]
- **Least privilege:** giving only the access that's needed. [[45 Security Fundamentals#Least Privilege|More]]
- **Left-prefix rule:** indexes work from their leftmost column. [[51 Indexing#Composite Indexes and Column Order|More]]
- **Legacy code:** code without tests. [[41 Refactoring#Working with Legacy Code|More]]
- **Locality:** programs tend to reuse nearby data. [[35 Computer Organization and Architecture#Locality|More]]
- **Lock or mutex:** lets only one thread into a section. [[37 Concurrency and Parallelism#Locks|More]]
- **Lost update:** one change silently overwrites another. [[52 Transactions and ACID#Concurrency - Lost Updates|More]]
- **malloc and free:** asking for and returning heap memory in C. [[38 Memory Management#Manual Memory - malloc and free|More]]
- **Memory hierarchy:** storage layers from fast and small to slow and big. [[35 Computer Organization and Architecture#The Memory Hierarchy|More]]
- **Memory leak:** memory that's never given back. [[38 Memory Management#Memory Leak|More]]
- **Migration:** a versioned schema change. [[50 Database Design#Safe Schema Changes|More]]
- **N+1 problem:** one query that causes many more. [[51 Indexing#The N+1 Problem|More]]
- **Namespaces:** a kernel feature that limits what a process can see. [[48 Docker#What Is a Container?|More]]
- **Observer:** one event, heard by all subscribers. [[43 Design Patterns#Observer|More]]
- **OOM killer:** Linux ending a process when memory runs out. [[36 Operating Systems#Key Words|More]]
- **OpenAPI:** a standard way to describe an API. [[44 API Design#Contracts and OpenAPI|More]]
- **Optimistic locking:** checking at save time that nothing changed. [[52 Transactions and ACID#Fix 2 - Optimistic Locking|More]]
- **Outbox pattern:** saving a message in the same transaction as the data. [[52 Transactions and ACID#Where Should a Transaction Begin and End?|More]]
- **OWASP Top 10:** the leading web security risks. [[46 OWASP Top 10#The Big Idea|More]]

- **Page fault:** a page isn't in RAM, so the kernel must load it. [[36 Operating Systems#Key Words|More]]
- **Parallelism:** running many tasks at the same instant. [[37 Concurrency and Parallelism#The Big Idea|More]]
- **Partial index:** an index on only some rows. [[51 Indexing#Partial Indexes|More]]
- **Pessimistic locking:** locking a row when you read it. [[52 Transactions and ACID#Fix 3 - Pessimistic Locking|More]]
- **Pipeline (CI):** the automated steps every change passes through. [[49 Continuous Integration and Delivery#A Complete Pipeline|More]]
- **Pipelining (CPU):** overlapping instructions, to finish more. [[35 Computer Organization and Architecture#Pipelining|More]]
- **Pointer:** a variable that holds an address. [[38 Memory Management#Pointers|More]]
- **Postmortem:** a blameless review after an incident. [[39 Software Development Lifecycle#Incidents and Postmortems|More]]
- **Process:** a running program with its own memory. [[36 Operating Systems#Processes|More]]
- **Proxy:** a stand-in that controls access. [[43 Design Patterns#Proxy|More]]
- **Query plan:** how the database will run a query. [[51 Indexing#Before and After|More]]
- **Race condition:** the result depends on timing. [[37 Concurrency and Parallelism#Race Conditions|More]]
- **Refactoring:** changing structure, not behaviour. [[41 Refactoring#The Big Idea|More]]
- **Reference counting:** freeing an object when nothing points to it. [[38 Memory Management#Reference Counting|More]]
- **Register:** a tiny, very fast slot inside the CPU. [[35 Computer Organization and Architecture#The Big Idea|More]]
- **Rollback:** undoing a transaction. [[52 Transactions and ACID#Commit and Rollback|More]]
- **Salt:** random data that makes each password hash unique. [[46 OWASP Top 10#A04 Cryptographic Failures|More]]
- **Scheduler:** decides which thread runs next. [[36 Operating Systems#The Scheduler|More]]
- **Selectivity:** how well a column narrows down rows. [[51 Indexing#Selectivity|More]]
- **Semantic versioning:** the major.minor.patch numbering system. [[39 Software Development Lifecycle#Version Numbers|More]]
- **Semaphore:** allows up to N holders at once. [[37 Concurrency and Parallelism#Other Tools|More]]
- **Signal:** a small message sent to a process. [[36 Operating Systems#Talking Between Processes|More]]
- **Singleton:** a class with one instance, often an anti-pattern. [[43 Design Patterns#Singleton|More]]
- **SOLID:** five principles of object-oriented design. [[42 SOLID Principles#The Big Idea|More]]
- **SQL injection:** input that gets run as SQL. [[46 OWASP Top 10#SQL Injection|More]]
- **Staging:** a practice copy of production. [[39 Software Development Lifecycle#Environments|More]]
- **Strangler fig:** replacing a system piece by piece. [[41 Refactoring#The Strangler Fig|More]]
- **Strategy:** a swappable algorithm. [[43 Design Patterns#Strategy|More]]
- **STRIDE:** six kinds of threat to look for. [[45 Security Fundamentals#Step 2 - Ask STRIDE Questions|More]]
- **System call:** asking the kernel to do something. [[36 Operating Systems#Kernel and User Space|More]]
